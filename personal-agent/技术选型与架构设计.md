> **关于 DSH 复用（勘察结论）**：DSH 运行时代码位于应用包内部（`app.asar/dsh`），应用包内 `packages/` 为空、需从 asar 解包访问，且其运行时依赖指向用户目录下的运行时副本。**把它作为库依赖引入是脆弱的**（应用更新即失效，asar 内不可写、不可打补丁）。因此本方案**零代码复用**，仅在"概念与格式层"参考其 Skill / 子代理 / 工具调用设计（概念借鉴不需要运行时依赖）。你的选择与工程现实一致。

## 1. 架构目标与硬约束

技术架构必须服务 PRD 里这几条不可妥协的需求，任何选型冲突时**以它们为准**：

| 编号 | 硬约束 | 对架构的直接要求 |
| --- | --- | --- |
| C1 | 哨兵层 24/7 可靠（NFR-R1..R6） | 存在一个**不依赖 UI 的常驻进程**；UI 崩溃不影响它 |
| C2 | 断网下定时提醒 100% 可用（NFR-R4） | 调度与幂等**不得依赖任何网络/模型调用** |
| C3 | 脱敏网关是唯一出口、零绕过（NFR-SP4） | 网关必须在**引擎层强制**，不能靠调用方自觉 |
| C4 | 员工崩溃不影响他人与哨兵（NFR-W1） | 每个员工**独立进程**；状态外置（无状态 worker） |
| C5 | 资源可控、机器不被占满（NFR-P5） | 三层并发上限 + 进程级资源约束 |
| C6 | 一切可追溯、可回放（NFR-W7） | 全链路事件化落库；时间可注入以便测试（NFR-M1） |
| C7 | 数据本地优先、向量不出机器（R34/K1） | 存储单文件本地；嵌入默认离线方案 |
| C8 | 跨平台一致（NFR-X1/X2） | 内核与平台层分离，平台差异只在 adapter 内 |

## 2. 技术选型总表

### 2.1 运行时与语言

| 层面 | 选型 | 理由 | 备选与否决理由 |
| --- | --- | --- | --- |
| 语言 | **TypeScript 5.x（strict）** | 与选定栈同构；PRD 里大量"结构化契约"（Skill/岗位/流程/交接单）用类型系统表达收益极大 | Rust 混合方案否决：初期复杂度不划算，性能瓶颈已由 SQLite 与子进程隔离覆盖 |
| 运行时 | **Node.js 24 LTS** | 你机器已有 Node 24 + pnpm 工具链；`node:sqlite`、`fetch`、`AsyncLocalStorage` 等原生能力齐全 | Bun 否决：原生模块与 Electron 集成生态仍不稳 |
| 包管理 | **pnpm workspaces** | Monorepo 必需；与现有工具链一致 | npm/yarn 否决：monorepo 体验与磁盘占用更差 |
| Electron 内 Node | Electron 自带 Node（**不混用系统 Node**） | 避免版本漂移；daemon 用系统 Node 或打包的 Node 二进制（见 §3.2） | — |

### 2.2 存储与数据

| 层面 | 选型 | 理由 |
| --- | --- | --- |
| 主存储 | **SQLite（`node:sqlite`，WAL 模式）** — *R0 spike 后由 better-sqlite3 改定* | 随 Node 运行时提供，**零原生依赖、无 Electron ABI 风险**；S2 实测 1 万向量插入 39ms、KNN 0.14ms，性能足够。better-sqlite3 在 pnpm 下 binding 常缺失（需额外构建配置），收益不抵风险 |
| 查询层 | **Kysely**（类型安全 SQL builder） | 编译期校验 SQL 与类型；迁移用其 migration 机制；比 ORM 轻、比裸 SQL 安全 |
| 迁移 | Kysely Migrator + 版本号 | 支持 PRD 要求的"格式带版本、升级有迁移提示"（NFR-M4） |
| 向量检索 | **sqlite-vec** 扩展（R0 已验证） | 与主库同文件；**两个实测约束**：① 扩展加载必须在**建库时** `{ allowExtension: true }`，事后开启会报错；② `node:sqlite` 把 JS number 一律绑定为 REAL，**vec0 主键必须用 BigInt**（`1n`）。兜底：`vec_distance_L2` 暴力比较亦可用 |
| 关键词检索 | **SQLite FTS5（内置 BM25）+ CJK 分词层** | 零依赖；但 S2 实测：**默认 unicode61 对中文只有 36% 召回**（把连续 CJK 当一个 token），trigram 更差（27%）。**必须加中文分词层**：CJK 单字切分 100%、bigram 91%。另注意 FTS5 的 `MATCH` 中**空格 = AND 而非 OR** |
| 全文正文 | 原文落文件系统（内容寻址），库里存指针 + 哈希 | 让"原文是唯一真相源、索引可重建"（FR-G103）成立 |
| 缓存 | SQLite 表 + 内存 LRU | 不引入 Redis；单机自用无需独立缓存服务 |
| 日志 | NDJSON 滚动文件 + 关键事件入 SQLite | 诊断靠文件（便宜），审计与回放靠库（可查） |

### 2.3 模型与 AI 能力

| 层面 | 选型 | 理由 |
| --- | --- | --- |
| 模型访问 | **Vercel AI SDK（`ai` 包）+ 自建 Provider 适配层** | 统一 streaming / tool-calling / 结构化输出；OpenAI 兼容、Anthropic、DeepSeek 等一套代码切换；**但网关必须包在它之外**（C3） |
| 结构化输出 | **Zod schema → JSON Schema → 模型 tool/response format** | 交接单、申请单、压缩摘要都是强结构，必须机器可校验 |
| 嵌入（默认） | **离线 BM25（FTS5）为主 + 可插拔 EmbeddingProvider** | 在"暂不做本地模型"前提下仍能保证**向量不出机器**：默认零嵌入；需要语义召回时再选本地 ONNX 或云端（见 §10 D3） |
| 嵌入（可选 A） | 本地 ONNX 小模型（如 bge-small，经 `onnxruntime-node` + `@huggingface/tokenizers`） | 纯本地、无外发；代价：~100MB 模型文件 + 原生依赖 |
| 嵌入（可选 B） | 云端 embedding API | 质量最省心；但**向量可被部分还原（R34）**，仅允许 L0/L1 内容 |
| 重排 | 初期启发式融合（RRF）+ 规则加权；预留 rerank 接口 | 不引入 cross-encoder（那需要本地模型，与当前前提冲突） |
| **云端 API 是唯一 LLM 路径** | **必须显式承认的后果** | 见 §5.1 —— 这改变了"数据不出机器"模式的能力边界 |

### 3.2 进程模型（关键设计）

| 进程 | 常驻 | 职责 | 崩溃影响 |
| --- | --- | --- | --- |
| **daemon** | ✅ 是（唯一 24/7 主角） | 调度、编排、内核、状态唯一所有者 | 由守护机制重启；**这是唯一不能倒的进程** |
| **Electron Main** | 通常常驻（托盘存在时） | 系统集成 + IPC 桥；**不含业务逻辑** | 哨兵继续工作（只是看不到通知？→ 见下） |
| **Electron Renderer** | 窗口存在时 | 纯 UI 渲染 | 无影响 |
| **Employee Worker** | 按任务 fork | 一次员工执行（无状态，语境从库重建） | 只影响该任务（回"就绪(被中断)"态） |

**两个必须讲清的点：**

1. **通知依赖 Electron Main**（macOS 原生通知需要应用身份）。因此：
   - 若 Main 崩溃，**哨兵仍在调度与落库**，通知走"补偿补发"路径 —— daemon 检测到通知投递失败会缓存，Main 恢复后补投（复用 FR-A3 的补偿机制，不新造一套）。
   - 备选强化：daemon 可调用平台 CLI 兜底通知（macOS `osascript`/`terminal-notifier`），保证"UI 全挂也能响"。
2. **daemon 用哪个 Node 二进制**：
   - 方案 A（推荐）：打包时随应用附带一份 **Node 运行时二进制**（~50MB），daemon 用它跑，**与 Electron 的 Node 解耦**。
   - 方案 B：Electron 的 `utilityProcess` 跑 daemon —— 省体积，但 daemon 生命周期被 Electron 绑定，**违背 C1**（Electron 更新/退出会带走它）。
   - **结论：选 A。** 这一条是"24/7 可靠"与"省 50MB"之间的取舍，我建议选可靠。

### 3.3 通信协议

| 项 | 设计 |
| --- | --- |
| 传输 | macOS/Linux：`~/Library/Application Support/<app>/daemon.sock`（UDS）；Windows：`\\.\pipe\<app>-daemon` |
| 帧格式 | NDJSON（一行一个 JSON 对象），避免粘包解析复杂度 |
| 协议 | JSON-RPC 2.0（请求-响应）+ 单向 notification（事件推送） |
| 事件流 | `task.updated` / `notification.created` / `worker.status` / `budget.updated` / `approval.requested` 等，UI 订阅式刷新（替代轮询） |
| 鉴权 | socket 文件权限 0600 + 随机 token（启动时写入仅本用户可读的握手文件） |
| 版本协商 | `hello` 握手带 protocolVersion；不匹配时 UI 提示升级而不是静默错乱 |
| 契约 | 所有 method/事件用 **Zod 定义在 `packages/ipc-contract`**，两侧共享类型 —— 编译期防错配 |

**为什么不用 Electron IPC 直连 `ipcMain` 做业务**：那会把业务绑死在 Electron 生命周期里（违背 C1），且以后无法做 CLI / 无界面模式。

### 3.4 平台适配层（差异隔离点）

所有平台差异**只允许出现在这一层**，内核不得出现 `process.platform === 'darwin'` 之外的分支逻辑：

| 能力 | macOS | Windows | Linux |
| --- | --- | --- | --- |
| 通知 | Electron Notification / `osascript` 兜底 | Electron Notification / Toast | Electron Notification / `notify-send` |
| 托盘/菜单栏 | Tray + Menu | Tray + 上下文菜单 | Tray（AppIndicator 依赖） |
| 自启 | LaunchAgent plist | 计划任务（登录触发） | systemd user unit |
| 凭据 | `security`（Keychain） | Credential Manager | Secret Service (libsecret) |
| 系统指标 | `os` + `system_profiler` | `wmic`/PowerShell | `/proc`、`/sys` |
| 软件调用/安装 | `open`/`osascript`/Homebrew | `start`/PowerShell/Chocolatey·winget | `xdg-open`/包管理器 |
| 权限引导 | 隐私与安全性跳转 | 设置跳转 | 通常无 |

## 4. 数据架构

### 4.1 存储布局（单机自用，一切可备份）

```
~/Library/Application Support/Aegis/          （Windows: %APPDATA%\Aegis）
├── aegis.db                  # SQLite 主库（WAL）
├── aegis.db-wal / -shm
├── blobs/<sha256[0:2]>/<sha256>   # 内容寻址的原文与产物（知识原文、日志附件、技能包）
├── snapshots/context/<task>/<ts>.json  # 上下文快照（可回滚）
├── skills/                   # 用户自定义 Skill（YAML，可版本管理）
├── roles/ teams/ workflows/  # 岗位/团队/流程定义（YAML）
├── logs/daemon-YYYY-MM-DD.ndjson
└── config.json               # 非敏感配置（敏感项在钥匙串）
```

**为什么原文放文件系统而不是塞进 SQLite**：满足"原文是唯一真相源、索引可重建"（FR-G103），且数据库体积可控（NFR-P7）。

| **通知** | `notification`、`channel`、`delivery_attempt`、`feedback`、`preference` | M1/M7 |

### 4.3 幂等与一致性（C2 的实现基础）

| 机制 | 设计 |
| --- | --- |
| 幂等键 | `occurrence` 表对 `(task_id, scheduled_at)` 建**唯一索引**；发送前先在事务内 `INSERT OR IGNORE`，插入失败即视为已发 —— **发送与否由数据库裁决，不由内存状态裁决** |
| 通知投递 | `delivery_attempt` 记录每次尝试；"已投递"以 attempt 成功为准；渠道失败进重试队列 |
| 任务恢复 | `work_item` 状态机迁移必须带 `version` 乐观锁，防两个 worker 抢同一任务 |
| 时钟 | 所有判断用**单调时钟 + 墙钟快照**双记录；检测到墙钟跳变（睡眠/改时间）触发补偿扫描（FR-A3/NFR-R6） |
| 事务边界 | 一个"任务触发 + 通知落库 + 审计写入"在一个事务里；外部副作用（发通知/调模型）通过**outbox 模式**异步执行，避免"发了但没记" |

### 4.4 虚拟时钟（NFR-M1 的落地方式）

所有时间读取**只允许**通过注入的 `Clock` 接口：

```ts
interface Clock { now(): Instant; monotonic(): number; setTimer(at: Instant, cb: () => void): TimerHandle; }
```

- 生产：真实实现。
- 测试：`VirtualClock` 可秒级模拟"30 天运行 / 合盖 8 小时 / 跨夏令时 / 跨时区"。
- **这是"验证 14 天无漏报"能自动化测试的唯一办法**，不做这个就只能靠真等 14 天。

## 5. 关键模块设计要点

### 5.1 模型访问与"云端 API 优先"的连带调整（重要）

你选了**暂不做本地模型**。这不是小决定，它会改变 PRD 里几处设计，需要同步修订：

| 受影响项 | 原设计 | 现实（无本地模型） | 建议处理 |
| --- | --- | --- | --- |
| §8.3 "数据不出机器"模式 | 本地模型 + 本地存储，L2 可用 | **无法处理 L2 内容**（脱敏后仍属敏感则不能发） | 明确降级为"**离线模式**"：哨兵全功能可用；员工层对 L2 内容**拒答并说明原因**（fail-closed 的一部分） |
| §7.13 FR-G117 压缩优先用本地小模型 | 本地压缩省成本 | 压缩**必须走云端**，是纯增量成本 | 三条替代优化：①**少压缩**（工具输出进上下文前先裁剪，源头控制）②压缩用**最便宜的模型档**③摘要缓存复用 |
| §7.12 K1 向量不出机器 | 本地嵌入 | **默认零嵌入**（只用 BM25），需要语义召回时再选本地 ONNX 或云端 | 见 §10 D3：建议**默认 BM25 + 预留 Provider**，向量能力延后 |
| 成本结构 | 本地模型摊薄 | **每一次调用都花钱**（含压缩、检索改写） | 预算与缓存从"可选"变"必需"：`prompt_cache`、日/月硬上限、异常增速熔断 |
| 隐私承诺 | 强（可全离线） | **中**（L2 必须脱敏后外发或拒答） | 文档与 UI 文案必须如实说明，不能宣称"数据不出本机" |
| 脱敏网关地位 | 重要 | **变成关键路径上的唯一防线** | 网关必须比原计划更早、更完整（见 §10 D2 的建议） |

> **一句话**：没有本地模型，就意味着"隐私"从"技术上保证不出门"变成"工程上尽量少出门 + 严格脱敏"。这是你能接受的取舍（你已选），但**必须写进产品说明**，不能默默降级。

### 5.2 脱敏外发网关（C3 的实现）

```
调用方（任何模块） → ModelGateway.complete()
                        │
                        ├─ 1. 载荷分级判定（来源标签 + 内容检测 + 默认 L2）
                        ├─ 2. 敏感项检测（检测器注册表，可插拔）
                        ├─ 3. 占位替换（会话级稳定占位符 + 本地映射表）
                        ├─ 4. 策略裁决（该级别能否外发？能否走此 Provider？成本是否超限？）
                        │     └─ 不允许 → fail-closed 抛错（不是降级放行）
                        ├─ 5. 写 OutboundAudit（不含原文）
                        ├─ 6. 真正调用 Provider（Vercel AI SDK）
                        └─ 7. 响应占位还原 → 返回调用方
```

**工程约束（防绕过）**：
- Provider SDK **只在网关内部被 import**；用 ESLint/Biome 自定义规则 + 依赖方向检查（`dependency-cruiser`）**禁止其他包依赖 `packages/model-provider`**。
- CI 里跑"零绕过审计"：扫描全仓是否存在绕过网关的 HTTP/模型调用（NFR-SP4、指标"绕过路径 = 0"）。
- 网关的失败是**硬失败**（fail-closed），调用方必须处理"不允许外发"这一分支，而不是拿到一个空结果继续编。

### 5.2.1 本机访问控制（口令锁）的技术设计（v0.7 新增，对应 PRD §8.5）

**范围界定（关键）**：口令锁**只作用于界面**，与 daemon 无关。

| 维度 | 设计 |
| --- | --- |
| 锁什么 | Electron 渲染层：未解锁时不渲染任务/历史/设置内容 |
| 不锁什么 | daemon 调度、通知投递、崩溃自恢复 —— **锁的是"看"，不是"跑"**（PRD FR-S26） |
| 口令存储 | Argon2id（或 scrypt）派生后的哈希 + salt + 参数，存本地文件 `~/.aegis/…/ui.lock`（0600） |
| **为什么不进钥匙串** | 钥匙串在系统账号解锁后即可被读取，用它保护"防同账号他人"是**无效的**；因此口令必须独立于钥匙串 |
| 忘记口令 | 无"找回"（本地无服务端可校验）。只能清除数据重来，需二次确认（PRD A3） |
| 自动锁定 | 界面空闲 N 分钟（默认 15）后回到锁屏 |
| 通知内容隐私 | 独立开关：锁定时通知只显示"你有 1 条提醒"，不带正文（PRD FR-S25b） |

**实现位置**：`packages/platform` 增 `UiLockStore` 接口（哈希读写），口令校验在 daemon 侧的
独立 RPC 方法中完成（`ui.unlock` 返回短时会话票据），避免把校验逻辑放进可被绕过的渲染层。

> ⚠️ **实现红线**：不引入账号、不联网校验、不提供凭据回显接口。
> 任何"需要登录才能后台运行"的实现都是设计错误（PRD §2.4.1）。

### 5.3 知识库与检索（默认零嵌入的可用方案）

| 阶段 | 检索方案 | 能力 |
| --- | --- | --- |
| M3（默认） | **FTS5 BM25 + 元数据过滤 + 查询改写 + 引用溯源** | 对文档/代码/专有名词效果好；**零外发、零模型成本、毫秒级** |
| M4 | + 上下文压缩联动、引用机械校验、冲突检测 | 满足"证据不足必须承认" |
| 可选增强 | 接入 EmbeddingProvider（本地 ONNX 或云端）→ 混合检索 + RRF 融合 | 语义召回提升；按 K1 需你决策 |

**分块实现要点**：结构化优先（Markdown 标题树 / 代码 AST 边界 / PDF 按页与段落），带 overlap，表格与代码块整体不切；每块存 `(doc_id, 位置, 文本哈希)` 以支撑引用校验。

**引用可解析的落地**：`citation` 表存 `chunk_id + 位置 + 内容哈希`；回答前用哈希校验原文未变，变了就标"引用已失效"（FR-G95）。**这是把"不许编"从提示词约束变成机械检查的关键一步。**

### 5.4 上下文管理器（四层模型）

```
ContextManager.assemble(task) → Prompt
   ├─ 锚定层      ← 从库按 task_id 读取（目标/DoD/禁止事项/已批决策），逐字拼装
   ├─ 受保护事实层 ← 结构化字段（数字/路径/提交号）序列化，不做摘要
   ├─ 工作层      ← 最近 N 轮原文 + 更早轮次的结构化摘要
   └─ 历史层      ← 只放"检索句柄"（chunk_id 列表），需要时再取
```

- **压缩自检**：压缩前后对锚定层做哈希比对（同一来源 → 同一文本），不一致直接回滚重压（FR-G114）。
- **快照**：压缩前完整上下文写 `snapshots/context/…`（FR-G112），保留期清理。
- **源头减量**：工具输出**先裁剪再入上下文**（只留结论 + 关键片段 + 指向 blobs 的指针），这比"塞进去再压缩"便宜得多（FR-G110）。

### 5.5 员工 Worker 模型（C4/C5）

| 项 | 设计 |
| --- | --- |
| 隔离 | 一任务一 `fork` 子进程；独立 cwd（工作区）；独立 env（仅注入该员工凭据） |
| 无状态 | Worker 不持有跨步状态；每步从 SQLite 读上下文、写结果（支持崩溃重放） |
| 通信 | 父进程 ↔ Worker 用 NDJSON over stdio + JSON-RPC（同 §3.3 协议，复用代码） |
| 资源 | `child_process` 无法直接限内存 → 用**步数与墙钟上限 + 采样监控 + 超限强杀**；Node `--max-old-space-size` 限制堆 |
| 并发 | 组织级 semaphore（全局/团队/员工三层），队列持久化在库中（重启不丢排队） |
| 权限 | 工具调用走**引擎层校验**（不是提示词约定）：查 `employee.permissions` → 拒绝即抛错并记审计 |
| 沙箱 | M4 起步用"独立目录 + 白名单命令 + 路径校验"；M6 视需要再上容器（`sandbox-exec` / AppContainer / bubblewrap 作为可选强化） |

### 5.6 软件调用与安装（M4–M6）

| 项 | 设计要点 |
| --- | --- |
| 能力清单 | `software` 表 + YAML 定义双轨（内置用 YAML 便于审阅，运行时同步入表） |
| 调用接口 | 统一 `SoftwareInvoker`：`cli` / `automation`(AppleScript·VBA·插件) / `gui`（默认禁用）三类适配器 |
| 引擎层强制 | 调用前查 `software_permission`（员工×软件×方式×目录范围），命中黑名单直接拒绝 |
| 安装 | 只走 `SourceAllowlist` 声明的来源；**锁定版本**；沙箱优先；安装后跑冒烟验证；失败回滚（记录 `install_job` 回滚点） |
| 高危 | `requires_admin=true` → 只生成 `manual_guide`，**绝不自动执行** |
| 截图 | 截图数据默认不落库不外发；只在本地内存用于识别，用完即弃（FR-G97/R28） |

### 5.7 事件与审计总线（C6）

- 所有关键动作发布**领域事件**（`task.fired`、`handoff.created`、`gate.approved`、`install.verified`…），落 `run_log`/`step`，推送给 UI 事件流。
- **回放**：给定 `work_item_id` 可重建完整时间线（PRD FR-G37/NFR-W7 的"可回放"由此实现）。
- 审计与业务日志分离：审计表**不含原文**（NFR-SP5），原文只在 blobs 里且受保留期管理。

| **D1** | daemon 运行时 | ✅ **打包随附独立 Node 运行时**，daemon 不依赖 Electron 生命周期 | 包体积 +~50MB；NFR-R1（24/7）不被 UI 绑架 |
| **D2** | 脱敏网关节奏 | ✅ M1 只做**钥匙串 + 审计骨架 + 检测器注册表骨架 + fail-closed 接口**；**完整网关闭必须在 M3 之前完成** | M1 无外发路径，不阻塞；接口第一天就位，避免 M3 返工 |
| **D3** | 嵌入方案 | ✅ **M3 纯 BM25（FTS5）起步**，预留 `EmbeddingProvider` 接口；语义召回不足时再接本地 ONNX（~100MB）或云端（仅 L0/L1） | 零外发、零模型成本；与"向量不出机器"不冲突 |
| **D4** | 向量扩展 | ✅ **sqlite-vec**（与主库同文件） | 单文件备份/迁移不变；极限性能让位于可维护性 |
| **D5** | 通知兜底通道 | ✅ **实现**：Electron 不可用时走平台 CLI（macOS `osascript` 等） | 消除"UI 全挂则提醒不响"的单点依赖 |
| **D6** | Worker 隔离强度 | ✅ 独立进程 + 目录隔离 + 命令白名单（**暂不上容器**） | 三平台一致；等要跑不可信代码再升级 |
| **D7** | 构建链 | ✅ pnpm workspaces + tsup/esbuild + electron-builder | 无异议 |
| **D8** | 开源策略 | ✅ **私有起步**，稳定后再决定 | 依赖许可证选择按"可私有分发"筛选 |
