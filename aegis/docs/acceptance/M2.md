# M2 验收：Skill + 规则引擎 + 本地监测

> 目标（PRD §5.2）：用 **3 个自建 Skill** 替代 3 件原本手动做的事，稳定运行 **7 天**。
> 本文件记录窗口与人工判据；自动证据由 `pnpm m2:report` 汇总到 `m2-report.md`（本机、已忽略）。

| 项 | 值 |
| --- | --- |
| 开始日期 | 2026-10-20 |
| 结束日期 | 2026-10-26 |
| 当前状态 | 进行中（第 1 天） |
| 并行说明 | R5 的 14 天观察继续进行；M2 由产品负责人授权并行开发 |

## 三个替代任务

| # | 原本手动做的事 | Skill / 监测器 | 判据 |
| --- | --- | --- | --- |
| 1 | 隔几天看下载目录里有没有新文件 | `downloads-change` + `files.downloads` | 新文件出现后收到通知；不重复刷屏 |
| 2 | 偶尔看磁盘还剩多少 | `disk-space-guard` + `system.host` | 低于阈值时收到告警；恢复后不误报 |
| 3 | 下载完大文件后手动检查 | `large-file-guard` + `files.downloads` | 超过 100MB 的文件出现时收到通知 |

> 设置 → 监测器 →「添加验收示例」会一次性补齐默认 Skills 与上述两个监测器（三个 Skill）。
> RSS/网页监测仍可手动添加，作为额外的第 4 个场景，不阻塞本验收。

## 7 天稳定性判据

- [ ] 3 个 Skill 均已启用并至少产生过一次 monitor 通知
- [ ] 7 天内 daemon 每天有 heartbeat（允许短暂重启）
- [ ] 没有因监测器导致 daemon 崩溃/反复重启
- [ ] 连续失败告警没有持续刷屏（failure 通知应可解释）
- [ ] 手动扫描/启停/增删监测器不破坏已有任务提醒
- [ ] 通知历史中 monitor 通知内容可读、无明显误报

## 自动证据

```bash
pnpm m2:report
# 输出 docs/acceptance/m2-report.md
```

先用「添加验收示例」把 3 个 Skill 跑起来，再开始计时；报告会把"配置了"与"实际触发过"分开统计。

报告会统计：

- 配置中的监测器与它们绑定的 Skill；
- 实际产生过通知的 Skill（monitor_cooldown）；
- monitor / failure 通知数量；
- monitor 错误日志；
- heartbeat 覆盖天数与运行缺口。
