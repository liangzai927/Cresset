# M3：本地知识库地基

> 目标：把项目文档喂进本地库，能检索到片段并给出**可溯源引用**；
> 有依据时让模型基于片段回答，无依据/不可外发时明确拒答。

## 1. 支持范围

- 导入：Markdown / TXT / Word(.docx) / RTF
- 单文件上限 2MB
- 分块：约 800 字符、重叠 100 字符，优先在段落/换行处断开
- 数据分级：L1 / L2（UI）；L3 可在协议层保存但不应外发
- 检索：CJK 友好的 FTS5；中文逐字切分，拉丁词按词
- 引用：`sourcePath + chunk ordinal + start/end offset`

## 2. 为什么不用 FTS5 默认分词

README F3：FTS5 的 `unicode61` 对中文子串检索只有 36%。

实现方式：

```text
文档 "项目知识库" → tokens: 项 目 知 识 库
查询 "知识库"     → tokens: 知 识 库
FTS MATCH: "知" AND "识" AND "库"
```

因此中文子串能命中，代价是索引更大。

## 3. 使用

设置 → 知识库：

1. 选择分级（L1 / L2）
2. 导入 Markdown / TXT / Word / RTF
3. 列表显示标题、分块数、来源路径
4. 输入中文/英文检索词
5. 结果里的「打开引用」用系统默认程序打开来源文件

无命中时明确显示：

```text
知识库里没有找到依据。
```

## 4. 安全边界

- 知识内容只存本地 SQLite
- 检索结果如果将来送给模型，**仍必须经过脱敏网关**
- L3 文档默认不应参与外发；拒答路径在后续 LLM 问答中实现
- 引用只暴露本地路径与偏移，不含模型生成的伪引用

## 5. 问答检索的查询处理

中文 FTS 是逐字索引，直接对整句做 AND 会把“在/哪/里/情况/可以”当成内容词，
导致明明有文档却零命中。

当前策略：

1. 先清理问句短语（是什么/哪里/多少/如何/包含/满足/存在…）
2. 再剔除单字停用词
3. 用 OR 召回候选
4. 按“命中查询词数量”排序
5. 至少命中 60% 内容词才认为有依据

这样“API Key 存在哪里？”能命中“API Key 存储”，
而“公司年会在哪一天？”不会因为“会/天”误命中。

## 6. 基于引用的问答与拒答

设置 → 知识库 →「问知识库」：

1. 本地检索最多 6 个片段；
2. 无命中 → 直接拒答，**不调用模型**；
3. 命中 L3 → 拒答，不外发；
4. 命中 L2 且外发上限为 L1 → 拒答，不消耗调用额度；
5. 有合规片段 → 经脱敏网关让模型回答；
6. 模型必须返回 JSON，引用编号必须来自本地命中；无有效引用 → 拒答；
7. 回答下方引用可点击打开来源文件。

拒答原因会明确显示，不会给一个看似可信的答案。

## 7. 当前限制

- 不支持 PDF（需要额外解析库）

- 没有 embedding / 混合检索 / 重排（M4）
- 没有 PDF/Word/网页摄取
- 没有增量索引与冲突裁决（M7）
- 问题检索采用去停用词后的 AND 匹配，复杂问法可能召回不足
