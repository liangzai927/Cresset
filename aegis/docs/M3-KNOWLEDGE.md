# M3：本地知识库地基

> 目标：把项目文档喂进本地库，能检索到片段并给出**可溯源引用**。
> 当前还没有“LLM 基于引用回答问题”；这层是检索与引用地基。

## 1. 支持范围

- 导入：Markdown / TXT（UTF-8）
- 单文件上限 2MB
- 分块：约 800 字符、重叠 100 字符，优先在段落/换行处断开
- 数据分级：L1 / L2（UI）；L3 可在协议层保存但不应外发
- 检索：CJK 友好的 FTS5；中文逐字切分，拉丁词按词
- 引用：`sourcePath + chunk ordinal + start/end offset`

## 2. 为什么不用 FTS5 默认分词

README F3：FTS5 的 `unicode61` 对中文子串检索只有 36%。

实现方式：

```text
文档 "项目知识库" → tokens: 项 目 知 识 库
查询 "知识库"     → tokens: 知 识 库
FTS MATCH: "知" AND "识" AND "库"
```

因此中文子串能命中，代价是索引更大。

## 3. 使用

设置 → 知识库：

1. 选择分级（L1 / L2）
2. 导入 Markdown / TXT
3. 列表显示标题、分块数、来源路径
4. 输入中文/英文检索词
5. 结果里的「打开引用」用系统默认程序打开来源文件

无命中时明确显示：

```text
知识库里没有找到依据。
```

## 4. 安全边界

- 知识内容只存本地 SQLite
- 检索结果如果将来送给模型，**仍必须经过脱敏网关**
- L3 文档默认不应参与外发；拒答路径在后续 LLM 问答中实现
- 引用只暴露本地路径与偏移，不含模型生成的伪引用

## 5. 当前限制

- 没有 LLM 问答（只能检索片段）
- 没有 embedding / 混合检索 / 重排（M4）
- 没有 PDF/Word/网页摄取
- 没有增量索引与冲突裁决（M7）

## 6. 验证

```bash
pnpm verify
```

`@aegis/knowledge` 测试覆盖：

- 中文检索与引用偏移
- 同路径重入库替换旧分块
- 内容未变幂等
- 无命中返回空
- 删除文档清理索引
